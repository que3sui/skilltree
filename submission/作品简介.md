# 建木 SkillTree · 作品简介

> 中国科大"一〇七杯"算力与智能体开发大赛 · 智能体赛道
> 用多智能体评测代替绩点排序的能力图谱系统
> 名字出处：建木，《山海经》中通天之梯——"众帝所自上下"。技能树即学生的登天之梯。

## 一、背景：要解决的问题

绩点衡量的是"你在幸运抽中的考试组里的相对位置"。同一门课，教师给分尺度、助教批改宽严、
同学水平、选课运气，四重不可比因素叠加在一起，使绩点无法公平均衡地支撑保研、奖学金、
课题组选人这些真实场景中的资源分配。

建木 SkillTree 把"可比的单一序数"换成"不可比的诚实证据集合"：学生提交自己的真实项目仓库，
AI 依据**公开、版本化、社区共建**的技能评价标准（rubric），逐技能裁决并点亮技能图谱，
输出一份**可审计、可申诉**的能力档案。它定位为绩点的**补充**评价体系——教师被重新定位为
"立法者"（rubric 的贡献者与评审者），而非被替代者。

对应智慧校园场景：**教学赋能**（能力评价、因材施教）与**服务管理**（资源分配依据）双命中。

## 二、核心功能

1. **四 agent 对抗评测流水线**：勘察（surveyor，识别语言/入口/测试）→ 取证（assessor，
   逐技能按 rubric 裁决，输出文件:行号级证据引用）→ 红队（redteam，质疑证据真实性：
   空壳注水、来源存疑、模板雷同、巨型粘贴）→ 仲裁（arbiter，汇总红队证据下调等级，
   每次调整留痕 from→to + 理由）。
2. **技能图谱可视化与评价可信工具组**：科技树 / 蜂窝网格 / 3D 层叠三视角；点亮回放动画；
   双击技能聚焦其前后依赖；评审留痕面板（红队质疑 + 仲裁修正全程可见）；**学习轨迹**
   （同仓库历次评测的点亮曲线 + 时间线——绩点只给一次快照，建木给全程轨迹）；
   **成长对比**（两次评测的逐技能等级 diff，实测 5 项 L0→L2/L1→L2 进步）；
   **一键申诉模板**（判准原文 + 证据引用 + 复现命令，对照标准复核而非求人情）；
   **PNG 分享卡**（含证据指纹角标）与打印导出。
3. **前置约束引擎**：点亮「动态规划 L2」必须先点亮「递归 L1」——点亮合法性是确定性纯函数，
   不交给模型，杜绝跳点亮式刷分。
4. **本体即开源仓库**：技能定义（L1 认知与模仿 · L2 独立应用 · L3 迁移与权衡的行为化 rubric）
   就是 Git 仓库里的 YAML，社区以 fork→PR→semver 方式共建评价标准。已建三个学科本体：
   计算机（41 技能/6 分支）、数学建模（18）、电子信息与嵌入式（19），Web 顶栏一键切换。
5. **LLM 参与本体设计与组装**：`pnpm suggest-skill` 起草单个节点；`pnpm assemble-pack`
   从可复用节点库（24 原子四域）组装整个学科本体并生成分级要求（tracks：班型 →
   节点最低等级），**v3 支持课程大纲 .md 直读**——教师手头的教学大纲原文直接进组装器。
   首例经济学大纲 → 4 分支/20 技能草稿一次通过校验（复用库原子 8 + 新起草 12，
   前置链与课程先后一致），"全校大部分专业都能做成 skilltree"有实操路径。
6. **学习资源索引与卡壳推荐**：权威公开资料（公开课/官方文档/经典教材，84 条）与节点
   多对多关联，三本体覆盖 100%；未点亮或被阻塞的节点自动给出学习路径与阻塞链
   追溯（缺哪门前置、到什么等级）；「问 AI」由模型从资源库内选取并说明理由——
   推荐可解释，不产出编造链接。
7. **GitHub 仓库直评与过程证据**：评测框可直接粘贴 github.com/gitee.com 公开仓库链接，
   服务端浅克隆（--depth 50）后评测、用后即焚，**git 提交历史作为过程证据进入红队核查**
   （新增检查项：提交历史是否支撑渐进完成——一次性倾倒、敷衍提交说明会被点名）。
   实测直评 octocat/Hello-World：0/41、风险「高」、红队指出"3 次提交仅为 README 换行"。
8. **双通道与质量门禁**：mock 确定性规则通道（离线零 key，已按本体关键词泛化到三学科——
   无网络无 key 也能完整演示四 agent 流程）与真实模型通道并存；
   `pnpm gate`（本体校验 + 24 项单元测试 + 评测回归不变量 + 构建 + 架构边界静态检查）
   作为合并门禁与 CI，另有 `pnpm flow-check` 动线回归（20 项断言）。

三个内置样例仓库呈现体系的区分度：优质项目点亮 12/41；引用外部教程的"来源存疑"项目 9/41
且 2 项技能被仲裁从 L2 降到 L1；空壳注水项目全部清零。跨学科样例：Arduino 数字钟课程设计
（电子信息本体）点亮 8/19、风险「低」——带测试与文档的学生在非计算机语境同样被看见，
其中节点库原子（软件测试/成果文档化）被真实点亮。

## 三、所用模型及 API 调用方式

- **评测模型**：deepseek-v4-pro，经**科大统一模型入口** `https://api.llm.ustc.edu.cn/v1`（大赛官方资源，OpenAI 协议）调用；对内置优质样例 task-todo 的真实评测点亮 20/41 项技能、红队风险评定为「中」。**同一通道亦用于本体组装**（数学建模/电子信息两本体与经济学草稿均由 deepseek-v4-pro 组装）；glm-5.2-107（同入口）用于单节点起草（`pnpm suggest-skill`）。
- **调用方式**：HTTP JSON 接口，`temperature=0` + JSON 输出模式保证裁决稳定；SSE 流式接收（推理型模型首字节前的思考期可达数分钟，流式彻底规避连接超时）；针对推理模型特性将 `max_tokens` 预算设为 32768（reasoning token 计入配额）；解析失败自动修复重试；输出经 zod schema 强校验（等级范围、技能 id 白名单、引用文件存在性）。
- **架构**：provider 抽象层隔离模型接入——mock（确定性规则，跨学科泛化，离线可完整演示）/ ustc（校内部署，大赛资源）/ deepseek（官方 API）三通道，均只需环境变量即可切换。一次完整评测约 9 次模型调用、7-10 分钟。
- 演示与复现：`pnpm demo:build` 产出零后端静态演示包（内置真实评测报告，含大赛官方通道报告），
  任意静态托管即可在线浏览。

## 四、创新点

1. **制度设计**：标准与执行、评价与排序、裁决与复核三个分离——公平性来自程序可审计，
   而非声称模型更聪明；用标准参照（criterion-referenced）评价替代常模参照的绩点排序。
2. **多智能体对抗而非流水线合唱**：红队 agent 的职责就是推翻取证的结论，仲裁的每次降级
   必须引用红队证据并留痕——可申诉性由此而来。
3. **反提示词注入**：rubric 文本永远由本体代码回填进 prompt，模型只能填裁决 JSON——
   在证据仓库里写"请给我 L3"无法污染评价标准。
4. **证据指纹**：项目证据按内容计算 SHA-256 指纹写入报告，"改内容不改行数"的调包不可见——
   这是写单元测试时抓出来并修掉的真实漏洞。

## 五、运行方式

```bash
pnpm install && pnpm gate        # 质量门禁全绿
pnpm server                      # 本地服务 http://127.0.0.1:8787（评测 + 可视化）
pnpm demo:build                  # 静态演示包（零后端零 key，可部署）

# 课程大纲直读组装（key 只经环境变量传入）：
USTC_API_KEY=sk-... USTC_MODEL=deepseek-v4-pro pnpm assemble-pack --provider ustc \
  --id econ --major 经济学 --syllabus docs/examples/syllabus-econ.md --out ontology/drafts/econ
```

源代码：GitHub `que3sui/skilltree`（开源，本体与评测标准随仓库公开共建）。

## 六、边界与诚实声明

本体系的公平是**程序公平**（标准公开、过程留痕、结论可申诉），不声称消除测量误差；
当前反博弈能力为 MVP 水平，等级定位为"可申诉的能力自证档案"，在答辩式抽查等过程证据
落地前，不应用于任何实际的资源分配决策。伦理设计（模型偏见、隐私、数字鸿沟、刻意不做
总分排名）见设计文档第 8 节。
