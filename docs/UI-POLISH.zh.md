# 界面打磨方法论 —— 从"能用"到"成熟产品"

> 本文回答一个问题：为什么自己做的界面常觉得"拥挤、笨重"，而成熟产品看起来轻松？
> 并以本项目科技树界面的两次迭代为实例。方法适用于任何前端项目。

## 1. 先诊断：拥挤与笨重从哪来

| 症状 | 病因 | 药方 |
|---|---|---|
| 拥挤 | 每个元素都在抢注意力（没有视觉重心） | 一个界面只允许一个"主角"，其余全部降噪 |
| 拥挤 | 靠边框/底色分组，而不是靠留白分组 | 删框，用间距与对齐表达归属 |
| 笨重 | 装饰多于信息：发光、渐变、大圆角、粗边框、阴影叠阴影 | 装饰预算：每个组件最多一种装饰手段 |
| 笨重 | 颜色太多且大面积使用 | 颜色只做小面积语义（状态、分支标识），大面积保持中性 |
| 不精致 | 间距/字号/颜色随手取值 | 设计 token：固定档位，禁止档位外的值 |

## 2. 六条可操作的规则（本项目实践）

1. **建立 token，拒绝随手值**。颜色 5 档中性阶（bg/surface/line/text×3）+ 少量语义色；
   间距 4/8 栅格；字号 11/12/13/17；圆角 7/8/9。所有组件只从 token 取值——
   一致性不是靠品味，是靠约束。
2. **视觉重心唯一**。本界面的主角是"点亮的技能"。因此：未点亮节点退为纯文字（无底无框），
   连线是背景网格（低对比、细线），顶栏按钮改 ghost。主角之外的一切都在"退后"。
3. **用留白分组，不用盒子分组**。分组信息由间距（列间距 > 节点高）与对齐表达；
   分隔线只在列表里用，且是 1px hairline。
4. **信息密度控制：一个节点一行**。旧版节点 48px 两行文字 + 状态标签 + 锁图标 + 等级点；
   新版 36px 一行：名字 + 等级点。被删掉的信息没有消失——进了悬浮提示与详情侧栏
   （渐进披露：hover/click 才出现的细节不算拥挤）。
5. **动效只做状态反馈**。150-400ms、ease-out、只作用于透明度/位移/颜色；
   删除一切"表演型"动画（大发光、脉冲、长闪烁）。慢而稳的 2.6s 连线流动是唯一的氛围元素。
6. **真实内容压力测试**。用最长的技能名（10 字）、两个极端状态（0/41 全灭、41/41 全亮）、
   最窄视口各截一张图检查。设计稿里永远好看，极端数据才暴露问题。

## 3. 打磨的流程（比规则更重要）

成熟产品的质感来自**高频小迭代**，而不是一次设计对：

```
改一版 → 截图 → 冷眼审视（隔 10 分钟或换人/换 AI 看）→
说出具体的病（"连线穿过了文字"而不是"感觉乱"）→ 只改这一处 → 再截图
```

- **具体化反馈**：把"感觉笨重"翻译成可执行的陈述（"渐变按钮+发光徽章+彩色边框同时出现"），
  每条对应一次最小修改；
- **对照参考系**：找 2-3 个你认可的成熟产品（Linear、Vercel、GitHub dark）截图并排对比，
  差异通常立刻可见（他们的边框更少、颜色更少、字重更轻）；
- **AI judge 当冷眼**：让模型按固定验收单（拥挤？笨重？可读性回归？极端状态？）逐页判定，
  它没有沉没成本，适合当第一道评审；人的直觉做最终裁决；
- **克制退出的勇气**：打磨的终点不是"加无可加"，而是"删无可删仍够用"。

## 4. 本项目两版对照（实例）

| 维度 | v1（首版） | v2（当前） |
|---|---|---|
| 节点 | 48px 双行：名称+状态文字+锁图标+等级点 | 36px 单行：名称+等级点 |
| 未点亮 | 深色填充+边框 | 纯文字，无底无框 |
| 点亮 | 分支色边框+发光+缩放动画 | 低饱和着色(9%)+彩色等级点，动画只做淡入 |
| 连线 | 高对比+发光+快速流动 | hairline，激活线 50% 透明度慢速流动 |
| 主按钮 | 琥珀渐变+发光 | ghost 边框按钮 |
| TIER 标签 | 每列重复 3-4 个 | 删除（纵向流已隐含层级） |
| 蜂窝 | r=25 内嵌两行文字 | r=17 无文字，点亮以纯色填充+单数字 |
| 报告元信息 | 指纹/哈希平铺在标题行 | 收进 title 悬浮提示 |
| 顶栏 | 毛玻璃+多元素强对比 | 纯色底、元素降噪 |

**删掉的每一样东西都换成了留白或渐进披露，没有损失信息。** 这就是"轻盈"的来源。
