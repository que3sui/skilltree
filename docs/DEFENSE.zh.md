# 答辩 PPT 大纲（决赛 2026-09-19/20）

> 结构：痛点 → 制度设计 → 四 agent → 三证据维度 → 演示流 → 伦理边界 → 演进路线。
> 口径与 docs/COMPETITIVE.zh.md §3 一致：**竞品都在"发证"，没有人在"举证"**。
> 每页标注「讲什么 / 放什么 / 战报锚点」，控制在 8 分钟讲述 + 4 分钟演示。

---

## P1 开场：绩点回答不了的问题（40s）

- 放：一张成绩单 + 三个问题（同一个 3.7：哪个 3.7？谁的 3.7？凭什么 3.7？）
- 讲：绩点不可比的四重来源——教师给分尺度、助教批改口径、同伴水平、选课组合运气。
  它是**排序工具**，不是**能力证明**。
- 金句：**我们要做的不是更好的绩点，而是绩点之外的另一种证据。**

## P2 洞察：评价问题 = 制度问题，不是算法问题（40s）

- 放：对比矩阵精简版（绩点 / 课程证书 / 徽章 / GitHub / 建木，5 行）
- 讲：竞品都在"发证"——课程平台证明你上过课，徽章证明你考过一次试，
  GitHub 证明你写过代码；没有一个能回答"**这份仓库能不能证明你具备 X 能力，为什么，
  不服去哪申诉**"。
- 差异化一句话：**护城河不是模型，是标准公开 + 证据链 + 过程留痕的制度设计；
  模型只是执行者，可替换、可复现。**

## P3 制度设计：三条铁律（60s）

- 放：三条铁律卡片
  1. **标准公开**——本体即开源仓库，41 条（cs）/19 条（eie）/18 条（mds）技能，
     每条 rubric 逐条可查、逐条裁决，版本号 + 内容哈希留痕；
  2. **证据可溯**——每条结论必须引用「文件：说明」，无引用不点亮（宁低勿高）；
  3. **结论可申诉**——仲裁留痕 + 一键生成申诉模板（逐条标准对照，不是求人情）。
- 讲：这三条分别对应评价的**效度、信度、程序正义**。

## P4 四 agent 流水线：让 LLM 互相制衡（60s）

- 放：勘察 → 取证 → 红队 → 仲裁 时序图（ARCHITECTURE §2）
- 讲：
  - **勘察**（surveyor）只描述事实不评价；**取证**（assessor）逐条对照 rubric；
  - **红队**（redteam）专职推翻——来源标记、测试真实性、空壳注水、git 历史渐进性；
  - **仲裁**（arbiter）按固定规则降级：flag 证据充分性 → 全清零；flag 文件来源 →
    引用者降 L1 待人工复核；warn 只进备注不降级。
- 金句：**单模型会讨好，四角色会制衡。**

## P5 三证据维度：内容 / 过程 / 留痕（60s）

- 放：三列卡片，每列一个实测战报
  - **内容**（仓库里有什么）：`task-todo` 12/41 点亮，每条带文件引用；
  - **过程**（怎么来的）：GitHub 直评 `octocat/Hello-World` = **0/41 + 高风险**，
    红队点名"提交 3 次，仅为 README 换行"——一次性倾倒识别；
  - **留痕**（谁判的怎么判的）：评审面板 = 模型/证据指纹/rubric 版本/四阶段耗时，
    报告可复现（同指纹同 rubric = 同结论）。
- 讲：内容证据防"没做"，过程证据防"抄的/倒的"，留痕证据防"黑箱"。

## P6 战报：红队咬了我们自己的样本三口（45s）

- 放：`modeling-comp`（数模课程设计）三轮迭代截图
- 讲：README 声称的残差图不存在 → 被 flag；无测试 → warn；"两周数据"实为 3 天 →
  描述降级。修复后风险 高→中、data.clean L2→L1。
- 金句：**红队对我们自己的样例下口，才敢说它对学生公平。**

## P7 跨学科：节点库 + LLM 组装（45s）

- 放：24 个可复用原子（通用/研究/数据/设计四域）→ eie pack 组装报告（ASSEMBLY.md）
- 讲：新专业 = 课程大纲输入 + 原子复用 + LLM 起草 + 人工审阅立法（PR）。
  实测：eie 19 技能中库原子**逐字复用**；`eie-clock`（Arduino 数字钟学生作业）×
  deepseek-v4-pro = 8/19 点亮、风险低——带测试与文档的学生在跨学科语境同样被看见。
- 本轮新增：mock 通道按本体关键词泛化——**离线也能演示三个学科**（cs 22/41、
  mds 5/18、eie 6/19），不依赖网络与 key。

## P9 伦理边界（40s）

- 放：负面清单卡片
- 讲：
  - **不越权**：建木是绩点的补充证据体系，不替代教师给分；L 等级不换算绩点；
  - **不惩罚缺失**：无 git 历史 = 过程维度缺席，**不因缺席降级**（只标注）；
  - **宁低勿高**：证据不足就是 0，申诉通道永远开着；
  - **数据边界**：本机单用户、证据不出边界、密钥多层拦截（脱敏闸宁可失败不落盘）。

## 预答 Q&A

- **Q 模型幻觉怎么办？** 裁决强制带引用，引用必须在证据文件名集合内（schema 校验）；
  红队专职对抗；仲裁只按规则降级不升级。报告可复现：同指纹同 rubric 同结论。
- **Q 学生把仓库做得像样但不理解怎么办？** 过程维度（git 渐进性）+ 红队
  模板雷同检查 + 申诉后人工复核；建木的定位是**举证**，不主张 100% 防伪，
  主张**每个结论可核查、可对抗、可翻案**。
- **Q 为什么学生信任你们的本体？** 本体开源、版本化、PR 立法路线；
  每条 rubric 与证据引用可逐条对照——不信任任何权威，信任程序。
- **Q 跟 GitHub Profile / 徽章的本质区别？** 它们是展示（display），我们是举证
  (evidence)：有没有标准、有没有引用、有没有过程、能不能申诉——四问之下全空白。
- **Q 规模化成本？** 单次评测 = 4 次模型调用 + 纯函数后处理，deepseek-v4-pro
  实测单次约 11 分钟、mock 通道 0.1 秒；批量/缓存（mtime 增量）已在服务端。
